## Cross-project content notes

- Replace every current generic description in `data/projects.json`; each one understates or mischaracterizes demonstrable repository content.
- Treat README claims as claims unless backed by checked-in source. The clearest mismatches are the absent GitHub Actions workflows in the AWS webapp and Snowflake/dbt/Tableau repositories, and the unverified incremental-model claim in the latter.
- “No GitHub languages” does not mean “empty” for the Snowflake/dbt/Tableau and atomic-detection repositories; both are non-empty, but are dominated by SQL/configuration, documentation, screenshots, and binary artifacts.
- Avoid “production-ready,” “enterprise-grade,” “real-time,” or quantified performance claims in cards. The repositories demonstrate thoughtful prototypes, labs, infrastructure examples, and offline-verifiable test fixtures, but do not supply production usage evidence.
- Keep every blueprint image free of embedded text. The visual identity can remain consistent through a dark technical grid, fine construction lines, restrained cyan/violet/amber/green/red signaling, and one project-specific system metaphor per card.
